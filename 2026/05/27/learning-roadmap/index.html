我的学习理念

编程不是”学”会的，是”做”会的。

看了 100 小时的教程不如亲手敲 10 个小项目。复盘总结比盲目刷课更重要。

学习路线

第一阶段：打好基础（1-3 个月）

  • 选一门语言深入（推荐 Python 或 JavaScript）
  • 理解变量、循环、函数、面向对象
  • 用 LeetCode 简单题巩固语法

第二阶段：动手做项目（3-6 个月）

  • 个人博客 / Todo App / 爬虫
  • 学会 Git 版本控制
  • 学会用搜索引擎和官方文档

第三阶段：深入底层（6-12 个月）

  • 计算机网络（HTTP、TCP/IP）
  • 操作系统基础（进程、内存、文件系统）
  • 数据库（MySQL + Redis）
  • 数据结构与算法

第四阶段：工程化思维

  • 设计模式
  • 系统设计
  • 代码质量与重构
  • 团队协作与 Code Review

每日习惯

推荐资源

类型 推荐
算法 LeetCode / 代码随想录
系统设计 System Design Primer (GitHub)
面试 牛客网 / 剑指 Offer
社区 GitHub / Stack Overflow / V2EX

小结

慢就是快。打好基础，做好笔记，保持热情。编程是一场马拉松，不是百米冲刺。

什么是索引索引就像书的目录，帮你快速定位内容，而不是从头翻到尾。 12345678-- 创建索引CREATE INDEX idx_name ON users(name);-- 查看索引SHOW INDEX FROM users;-- 删除索引DROP INDEX idx_name ON users; 索引类型 类型 说明 适用场景 B+Tree 默认索引类型 等值查询、范围查询 Hash 哈希索引 精确等值查询 Full-Text 全文索引 文本搜索 Unique 唯一索引 唯一约束字段 最左前缀原则联合索引 (a, b, c) 相当于创建了三个索引： (a) —— ✅ 生效 (a, b) —— ✅ 生效 (a, b, c) —— ✅ 生效 (b, c) —— ❌ 不生效（跳过了 a） 12345678-- 联合索引CREATE INDEX idx_abc ON orders(a, b, c);-- 会用到索引SELECT * FROM orders WHERE a = 1 AND b = 2;-- 不会用到索引（不符合最左前缀）SELECT * FROM orders WHERE b = 2 AND c = 3; EXPLAIN 分析1EXPLAIN SELECT * FROM users WHERE email = "test@example.com"; 关注字段： 字段 含义 type 访问类型（ALL < index < range < ref < const） key 实际使用的索引 rows 扫描行数 Extra Using index（覆盖索引）/ Using filesort（需要优化） 优化建议 WHERE、JOIN、ORDER BY 字段建索引 避免 SELECT *——用覆盖索引 避免在索引列上使用函数（如 WHERE YEAR(date) = 2024） 定期分析慢查询日志 小结 索引不是越多越好，每个索引都会拖慢写入速度。建在查询频繁的字段上，用 EXPLAIN 验证效果。
